# P-B.9 manual host acceptance — disposable owned collections only

Use the **matching P-B.9 extension and plugin**. Keep separate server-private backups of the entire host. Never test empty/delete/restore on production collections until this runbook passes on disposable data. The VectHare obsolete purge button is outside this milestone.

1. Start with a disposable, provisioned, fully managed-v2 saved-chat/lorebook collection on LanceDB, Vectra, then Milvus. Confirm the browser shows both the Qdrant M3 workspace and the separate M4 backend selector. Switch backend and source; inspect must return a server-authenticated complete physical inventory (or explicitly refuse with an actionable error). Never infer whole-collection correctness from saved-source pages.
2. Capture and verify backup. Record the returned backup UUID, logical key, inventory count and digest. Confirm no physical mutation occurred; verify backup remains server-private. Test a failed/changed backup; the browser must refuse planning.
3. On each backend, attempt `empty` for a disposable owned collection. The server must issue a one-use plan; wrong typed phrase must not dispatch. After explicit confirmation, verify the receipt, new zero-row active generation, old physical collection still present and managed registry tombstones. Check saved chat source remains intact.
4. Repeat with `restore` using a backup permitted by the server's M4 generation contract. Independently inspect the new active generation and record count. Run a text query against restored source. Retained physical history must remain accessible to privileged server inspection.
5. Test `delete` only on a separate canonical owned collection with verified backup, as server policy may refuse deletion after cutover. Verify physical absence and registry tombstone; confirm an unowned or legacy collection is rejected without mutation.
6. Simulate stale source edits, changed registry, changed embedding profile, changed inventory, browser/backend/source switching during requests and plan expiry. All should refuse safely. Simulate a response being lost **after** dispatch; the browser must prevent replay and direct to server operation evidence rather than retry.
7. Reopen the Database Browser, restart SillyTavern/plugin and re-inspect inventory and receipts. Record all backend errors, M4 operation IDs and host logs. If any step is uncertain, DO NOT reissue or manually unlock the operation without independent server adjudication.

**Completion criteria:** each backend proves owned inspection, backup, backup verification, empty, restore and admissible deletion on real disposable data; stale/foreign/uncertain tests refuse; host restarts and independent physical readback demonstrate consistency. P08 must remain unaccepted until these are recorded.
