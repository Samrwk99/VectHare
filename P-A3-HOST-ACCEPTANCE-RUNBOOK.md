1. **Embedding setup (P01–P03):** In Server-managed Embeddings choose your local provider. Configure its actual loopback endpoint and port (example: a llama.cpp `/v1/embeddings` service on port 8123; Ollama uses `/api/embed`); select the real served model and exact embedding dimension. Save and run **Test server embedding**; reload and verify the profile survives. Then intentionally set a wrong dimension, unreachable port and untested profile: all must refuse *before* any DB action. Check that settings do not expose raw credentials.
2. **First-use empty DB (P01/P05):** Select a *saved* chat and the desired Qdrant/LanceDB/Vectra/Milvus backend. Run Sync. Expect one consent for new owned collection if unprovisioned, then consent for source records, then verified receipts; no `M1_EMBEDDING_PROFILE_REQUIRED` if tested. Repeat after editing a message and try Repair. Repair should update changed messages **and insert missing ones**, not use `chunks/delete` or `getSavedHashes`. Deleted/swiped/orphaned records must be flagged for review rather than silently removed.
3. **Large chat and interruption (P06):** Test a saved chat containing >80, then about 250, then 1000 records if practical. Expect progress up to the **entire** saved-source count, no 80-record cutoff. Pause then resume; Stop midway. A paused/interrupted or uncertain operation must not show successful completion. Check verified receipts before re-running; do not auto-retry ambiguous mutations. Change or switch the source during a run: it must stop and report the mismatch.
4. **Generation retrieval (P04):** Enable F09b verified-v2 injection on a populated saved chat, send a relevant query, check that server-managed embedding is called and that a fenced memory block is registered within the host prompt budget. Test with llama.cpp and another supported provider. Switch chat/provider during request: no stale prompt block should survive. Expect condition-bearing World Info results **not** to be automatically injected (M6 pending).
5. **Diagnostics (P19):** Embedding generation test must work using the saved profile without legacy chunk writes; storage diagnostic must show **SKIPPED / UNVERIFIED**, with no test vectors left behind. A storage 'pass' is *not* expected before the safe managed-fixture work.
6. **Cross-platform/backend:** Test the actual installed server and plugin on your host with all four backends/configs you use. The fixture suite alone doesn't prove live connectivity or final model consumption.

Capture exact UI status, plugin log error codes, applied-operation receipts, chosen provider/model/port (omit credentials), backend and whether the chat was saved. Any failed acceptance item should remain open; do not call the whole P task fully certified.
