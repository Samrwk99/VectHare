# F09b.6 — Disposable host acceptance runbook

**Prerequisites:** Full backup of the normal SillyTavern deployment, a disposable user/profile, both matching F09b.6 packages, a working F09b.5 managed embedding profile and a distinct new F03-provisioned v2 collection per saved source/backend. Confirm exact S11 plugin fingerprint and backend binding. Do not use valuable historical vectors.

1. Create a saved lorebook via the normal SillyTavern UI. Give at least two enabled entries unique stable numeric UIDs and nonempty content, and one disabled entry. Check the source exists within the authenticated user's `worlds` directory and F01 attestation accepts it. In the F09b.6 panel enter the lorebook name without `.json` and **Preview**. Confirm enabled entry UUIDs and status only; no contents, vectors or credentials in API response. Preview must not change DB state.
2. Create/bind/provision a *new* v2 lorebook collection with the same F09b.5 source/model/dimension/metric. Consent to **Apply selected saved record**. Verify one and only one record inserted with correct text/vector, scope and metadata after S04 readback. Preview again and confirm `IN_SYNC` for the saved entry.
3. Edit the same saved entry through the host UI without changing its UID. Preview must show one `UPDATE_PENDING_EMBEDDING`; apply with fresh consent and confirm same UUID, next revision and exact new content after readback. Change the file *between preview and apply*; expect stale fingerprint refusal. Change it during embedding; expect fail-closed operation, not a write.
4. Change entry order; IDs must remain stable. Duplicate/remove the UID, replace the file with a symlink, insert invalid/oversized content or remove source ownership; expect refusal. Disabled or deleted source entries must **not** cause automatic vector deletion or false complete-inventory claims.
5. For a saved solo/group chat, verify the **actual host format** includes a literal string `chat_metadata.summary` in the first saved JSONL header. If it is absent or stored differently, record an unsupported-format finding; do not rewrite a real chat to fake compatibility. If present, create a new F03 chat collection, preview the summary, and apply one explicitly selected record. Verify the summary UUID is separate from ordinary saved-message IDs and no hidden LLM summary generation occurs.
6. Repeat across Qdrant, LanceDB, plugin Vectra and Milvus **in an isolated host**. Verify actual embedding profile matching and physical readback, cross-user isolation, cross-lorebook isolation, branch/source identity changes, restart persistence and genuine backend revision constraints. Failure to attest any backend must keep that backend's matrix denied.
7. Simulate a network timeout after mutation dispatch. Verify the S04 receipt and managed registry record remain pending/UNCERTAIN and there is no automatic retry. Inspect manually using existing read-only receipt tools; never clear a pending intent simply because physical presence or absence appears favorable.
8. Check the browser gateway and direct HTTP handler reject forged text, vector, record IDs, owner/collection, path selectors, missed consent, wrong origin, non-supported embedding source, stale source fingerprints, and attempts to use native Standard/legacy collections.

**Fail conditions:** unexpected mutations, source text or vector returned in preview, cross-user data visibility, edited/uncertified record overwrite, unregistered historical record adoption, file race bypass, unsafe retry, wrong physical collection, purge, automatic orphan deletion, production-matrix activation or an unproved summary format claimed as supported.

A passing disposable-host run establishes only evidence for the tested path; it is not by itself F09c/F10b/F12b certification.
