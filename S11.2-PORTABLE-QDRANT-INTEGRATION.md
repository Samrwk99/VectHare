# S11.2 — Matched S10.1 portable user-directory fix

**Symptom:** `HTTP 403; S03_USER_DIRECTORY_UNVERIFIED` during Qdrant backend initialization, after the S11.1 browser configuration fix.

**Root cause:** S10's S03 middleware required `req.user.directories.vectors` to be absolute and already present, even though the SillyTavern host can supply paths derived from a relative `DATA_ROOT`.

**Server fix in Similharity S10.1:** Resolve native Node relative and absolute host paths; anchor to the trusted authenticated user root, create only the missing empty vectors folder under that root; reject mismatched/symlinked vectors paths and user collisions. No browser path can supply identity or storage scope.

**Extension change in VectHare S11.2:** Pin S10.1's exact plugin version and new source fingerprint in `utils/s11-plugin-compatibility.js`; retain S11.1's fix that sends a configuration selector rather than browser credentials to `/backend/init/qdrant`. All E02/S01–S11 safety restrictions remain.

**Install both packages together**, replacing the S10 + S11.1 development pair. A mixed pair will correctly fail the build-compatibility check. Restart SillyTavern after replacing the plugin (server changes require a restart).

**Separate prerequisite:** Set up the protected per-user `SIMILHARITY_SERVER_CONFIG_DIR` and `server-connections.json` as detailed in the plugin's `S10.1-TERMUX-SETUP.md`. The directory fix cannot cure a missing server config or an unavailable Qdrant server.

**Verification:** 226/226 plugin offline tests and 27/27 targeted extension tests passed; S11.2/S10.1 offline pair compatibility passed. Live Termux/Windows/Qdrant testing was not performed. Writes remain disabled and no public v2 read execution is enabled.
