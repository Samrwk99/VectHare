# S06 handoff — Qdrant backend completion

1. **Host/source authority first:** Validate the actual SillyTavern `req.user` and chat/lorebook/branch ownership model on a disposable host. Implement an authenticated, durable source-grant/collection binding deriving physical mappings only from trusted server state. Do not accept `authorized:true`/`provenance:SERVER_VERIFIED` from HTTP bodies. In S05 those fields are internal test contracts, not proof from the caller.
2. **Qdrant v2 schema:** Verify Qdrant version and supported payload index types; create a disposable v2 collection with the canonical S02 scope and physical UUID ID. Add payload fields `userScopeId`, `collectionId`, `type`, `sourceId`, `branchId` (empty marker for branchless scope), `recordId`, `physicalId`, `revision`, `text`, `textHash`, `vectorHash`, `metadata`, `metadataHash`, `embedding`. For branchless records use a normalized explicit empty-string branch value and adjust/confirm backend filters; never risk broad ambiguous legacy filters.
3. **Live scoped read acceptance:** Compare actual Qdrant scroll/search/get behavior against `s05-backend-reads.js`, verify payload projection, vector structures, score semantics, empty/error discrimination, cursors and 1,050+ records. Demonstrate tenant A/B and branch A/B isolation with same text/hash.
4. **Safe insertion/update/deletion:** Implement backend adapter with Qdrant native scope filters, expected revision/conflict handling, non-destructive dimension rejection, stable physical IDs, operation ID and independent readback. Investigate concurrent/multi-process atomicity and do not assert unsupported guarantees.
5. **S04 engine integration:** Bind approved source grants to S04 server-side `authorize`; supply the verified adapter `getRecord` and write methods; leave public submit gated until repeated real-backend tests with restart and failures.
6. **Consistency:** Distinguish bounded display pages from complete stable inventory; verified export requires quiescence/snapshot guarantees, checksums and repeat validation. No arbitrary `total` from a page length.
7. **No legacy migration cutover yet:** S09 must implement backup/dry-run/copy/rollback and address ambiguous old hash-only identities. Do not silently re-use legacy physical names.
8. **Acceptance artifacts:** Per operation PASS/FAIL/BLOCKED/UNPROBED, exact deployed plugin/backend hashes and versions, sanitized requests/response contracts, hostile overlap tests, restart tests and rollback procedure. Keep all unsupported operations denied.

After S06, S07 will implement and certify equivalent Milvus behavior; S08 handles LanceDB and Standard/Vectra. S11 completes VectHare host/final-prompt integration.
