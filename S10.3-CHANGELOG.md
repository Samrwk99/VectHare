# S10.3 / S11.4 — GUI-first database connection fix

**Purpose:** Correct the S03/S10 configuration regression that caused `S03_SERVER_CONFIG_MISSING` when local Qdrant was available but no admin-managed server config file existed. Make Qdrant and Milvus connection setup accessible from the VectHare GUI rather than requiring environment variables and manual private JSON files.

## Plugin — S10.3

- Local Qdrant `configId=local` works out of the box on server loopback `127.0.0.1:6333`.
- Authenticated per-user `/v2/connections/:backend` GET/PUT/DELETE endpoints manage Qdrant local/cloud and Milvus server-side connection profiles.
- Config stored under the authenticated user root (`.similharity-private`); restrictive POSIX modes, symlink checks, atomic writes, serialization of same-process config mutations.
- Cloud credentials never returned in status, health, error or capability responses; no automatic transfer to another endpoint on hostname change.
- Qdrant redirects rejected to avoid forwarding an API key.
- Persisted config resolution wired into the S03 per-user BackendPool; initialized instances are invalidated on GUI configuration changes.
- Public vector mutation routes remain fail-closed.

## Extension — S11.4

- Qdrant connection fields re-enabled in UI; users can save and test local port or HTTPS cloud URL/key.
- Milvus host/address/token/username/password configuration saves server-side; Milvus init no longer forwards forbidden browser configuration.
- Connection status and removal controls added; credential inputs are write-only and cleared after Save.
- New configuration requests explicitly audited in E02 gateway while all unverified v2 vector operations remain blocked.
- Qdrant diagnostics report the server-effective endpoint rather than a browser setting that the plugin ignored.
- Exact S10.3 plugin version/source fingerprint pinned in S11.4 compatibility discovery.

## Known limits

- No real Termux/Windows/SillyTavern/Qdrant/Milvus acceptance was run here.
- S10.3 still reports `publicV2ReadsEnabled=false` and `publicV2MutationsEnabled=false`; safe connection configuration is **not equivalent** to usable memory insert/edit/delete.
- Server connection storage is scoped to the authenticated SillyTavern user root; OS filesystem administrators remain able to read it, as with other server-side credentials.
- Cloud hostname DNS rebinding and untrusted multi-user hosting require deployment-level network controls; do not expose a test installation to untrusted networks.
