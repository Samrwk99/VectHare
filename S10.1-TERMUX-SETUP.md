# S10.1 — Qdrant private connection setup (Termux)

The S10.1 directory fix resolves `S03_USER_DIRECTORY_UNVERIFIED` when the host supplies relative data-root paths. **It does not configure the remote backend.** Set this up only in a disposable SillyTavern installation.

1. Confirm Qdrant itself responds from the SillyTavern execution environment:
   `curl -fsS http://127.0.0.1:6333/collections`.
2. Find the authenticated SillyTavern profile handle (`default-user` for the usual single-user default, otherwise use your actual handle). **Do not guess if multi-user mode is enabled.**
3. In Termux, prepare private files before starting SillyTavern:

```sh
export SIMILHARITY_SERVER_CONFIG_DIR="$HOME/.similharity-server"
mkdir -p "$SIMILHARITY_SERVER_CONFIG_DIR"
chmod 700 "$SIMILHARITY_SERVER_CONFIG_DIR"
PROFILE_HANDLE='default-user'   # replace with actual authenticated profile handle
USER_HASH="$(node -e 'process.stdout.write(require("node:crypto").createHash("sha256").update(process.argv[1]).digest("hex"))' "$PROFILE_HANDLE")"
mkdir -p "$SIMILHARITY_SERVER_CONFIG_DIR/$USER_HASH"
chmod 700 "$SIMILHARITY_SERVER_CONFIG_DIR/$USER_HASH"
cat > "$SIMILHARITY_SERVER_CONFIG_DIR/$USER_HASH/server-connections.json" <<'JSON'
{
  "schemaVersion": 1,
  "backends": {
    "qdrant": { "url": "http://127.0.0.1:6333" }
  }
}
JSON
chmod 600 "$SIMILHARITY_SERVER_CONFIG_DIR/$USER_HASH/server-connections.json"
```

4. Start SillyTavern **from the same shell** (or add the export to the startup script). Do not put the config under the public or user vector directories.
5. Install S10.1 plugin + S11.2 extension together and restart SillyTavern.
6. Check `/v2/build` or the VectHare plugin compatibility indicator, then retry Qdrant init.

**Expected:** The directory 403 should no longer occur for a valid authenticated host root. A missing configuration will instead report `S03_SERVER_CONFIG_MISSING`; a Qdrant network/backend error requires separate diagnosis. No public vector writes are enabled.

**OS portability:** The plugin uses Node's native `path` APIs. On Windows, use an administrator-controlled private absolute directory and appropriate Windows ACLs instead of POSIX `chmod`. `127.0.0.1` only addresses a Qdrant process accessible from the same network namespace as SillyTavern.
